Welcome to TurtleTracerLib! This guide will walk you through creating your first autonomous program using the library.

## Prerequisites

Before you begin, ensure you have:

1.  Installed TurtleTracerLib in your project (see [Installation](/turtle-tracer-lib/installation/)).
2.  Configured your robot's hardware map (motors, sensors) in the Driver Station or `FtcRobotController`.

## The Recommended Workflow

The modern TurtleTracerLib workflow is "Visualizer-First":

1.  **Design** your path in TurtleTracer.
2.  **Export** the path as a complete Java OpMode.
3.  **Run** the generated code on your robot.

This approach eliminates the need to manually write complex geometry code and ensures your paths are visualized correctly before you even touch the robot.

:::caution[Deprecation Warning]
Manual path coding (writing `PathBuilder` code by hand) is **deprecated** and will be removed in version **2.2.0**. We strongly recommend using [TurtleTracer](/turtle-tracer/getting-started/) for all path creation.
:::

## Creating Your First Path

### 1. Open TurtleTracer

Go to the [TurtleTracer](https://github.com/Mallen220/TurtleTracer) (or your hosted instance).

### 2. Draw a Path

1.  Click the **+** (Add Path) button or press `P`.
2.  Click on the field to place your starting point.
3.  Click again to place the end point.
4.  Drag the control handles to shape the curve if desired.

### 3. Export Your Code

When you are ready to export, you have two options: a standard **Java OpMode** or a **Command-Based** structure.

<Tabs>
   <TabItem label="Standard OpMode (Default)">
   
    Use this option if you want a standalone `OpMode` that handles the path following logic directly.

    ### Steps
    1.  Click the **Export** button in the top right corner.
    2.  Choose **Java Code** from the menu, or **Kotlin Code** if your team writes Kotlin.
    3.  Check **"Generate Full Class"**.
    4.  Enter your team's package name (e.g., `org.firstinspires.ftc.teamcode`).
    5.  Click **Copy Code**.
    6.  Paste the code into a new Java (or Kotlin) file in your Android Studio project.

    ### Key Components
    -   **`pathState`**: A state machine variable that tracks which segment of the path is currently running.
    -   **`Paths` Class**: Contains all your generated `Path` definitions.
    -   **`autonomousPathUpdate()`**: The logic that switches between paths and waits for completion.

   <TabItem label="Command-Based (SolversLib)">
    Use this option if you are using a Command-Based framework (like SolversLib). This generates a `SequentialCommandGroup` rather than a full OpMode.

    ### Steps
    1.  Click the **Export** button in the top right corner.
    2.  Select **Sequential Command** as the format, then choose **SolversLib**, **NextFTC**, or **Ivy** as the target library. NextFTC and Ivy output is experimental.
    3.  Enter your team's package name, and use the **Language** switch to choose Java or Kotlin.
    4.  Click **Copy Code** (or **Save to File**).
    5.  **Important**: Unless you turn on **Embed Pose Data**, this method requires you to put the project file (`.turt`) on your robot as well, because it uses `TurtleTracerReader` to load points dynamically. The example below uses SolversLib.

    **Ivy output:** Ivy builds commands with static factories rather than subclassing, so the generated class returns a `Command` instead of extending one. Call `Scheduler.reset()` in `init()`, start the routine with `new AutoPath(follower, hardwareMap).command().schedule()`, and call `follower.update()` and `Scheduler.execute()` every loop.
